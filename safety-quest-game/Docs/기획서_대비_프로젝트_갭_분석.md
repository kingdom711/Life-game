## ❌ 미구현 항목 (Critical)

### 1. 교육 게이팅 (Education Gating) — 우선순위 ★★★

**기획서 약속**:
> "교육 미완료 시 다른 퀘스트 잠금 처리"
> "오늘의 안전 교육을 먼저 완료해주세요"

**현재 상태**: 미구현

**상세 분석**:
- `educationManager.js`에 `checkWorkPermission()` 함수가 정의되어 있음
- `EducationRequiredModal.jsx` UI 컴포넌트도 존재함
- **그러나** `Dashboard.jsx`(L149-157)와 `DailyQuests.jsx`(L1-52)에서 해당 함수를 **호출하지 않음**
- 교육을 건너뛰고 다른 퀘스트를 자유롭게 수행할 수 있는 상태

**영향도**: 기획서에서 "안전교육 이수율 100%"의 **유일한 근거**. 미구현 시 기획서 핵심 주장이 무력화됨.

**구현 방향**:
- `Dashboard.jsx`, `DailyQuests.jsx`에서 `checkWorkPermission()` 호출
- 미이수 시 교육 외 퀘스트 카드에 잠금 오버레이 표시
- `EducationRequiredModal.jsx`을 실제 연동

**관련 파일**:
- `src/utils/educationManager.js` — checkWorkPermission() (L298-320)
- `src/components/EducationRequiredModal.jsx` — UI 존재
- `src/pages/Dashboard.jsx` — 게이팅 호출 누락
- `src/pages/DailyQuests.jsx` — 게이팅 호출 누락

### 2. 체크리스트 UI — 우선순위 ★★★

**기획서 약속**:
> "안전 체크리스트 1건 작성 (100P, 2분 소요)"
> "관리감독자가 작업자 체크리스트 2건 검토·피드백"

**현재 상태**: API만 존재, UI 미구현

**상세 분석**:
- `checklistApi.js`(L7-88)에 `submitChecklist()`, `getMyChecklists()`, `getChecklistDetail()` API 메서드 정의됨
- 퀘스트 정의 `daily_checklist_1`(questsData.js)에 체크리스트 제출 요구 명시
- **체크리스트 작성/제출 UI 컴포넌트가 없음**
- 작업자가 실제로 체크리스트를 작성할 수 있는 화면 자체가 부재

**영향도**: 역할별 퀘스트 시스템의 기반. 이것이 없으면 관리감독자 검토(항목 6) 연계도 불가.

**구현 방향**:
- 체크리스트 작성 모달/페이지 컴포넌트 신규 생성
- 오늘 작업에 맞는 안전 점검 항목 목록 제공
- 체크 완료 후 제출 → 퀘스트 완료 연동

**관련 파일**:
- `src/api/checklistApi.js` — API 정의 (존재)
- `src/data/questsData.js` — daily_checklist_1 퀘스트 정의 (존재)
- `src/components/` — 체크리스트 UI 컴포넌트 (미존재)

### 3. 사진 업로드 기능 — 우선순위 ★★★

**기획서 약속**:
> "현장 사진 3장 촬영·제출 (150P, 3분 소요)"
> "현장 사진 일일 기록 → 위험 상황의 시각적 증거 축적 및 조기 발견"

**현재 상태**: 완전 미구현

**상세 분석**:
- `questsData.js`(L78-94)에 `daily_photo_1` 퀘스트 정의만 존재
- 사진 업로드 API 없음
- 사진 업로드 UI 컴포넌트 없음
- 사진 저장/관리 로직 없음

**영향도**: 작업자 일일 퀘스트 5개 중 1개(150P)가 수행 불가. 기획서의 "데이터 기반 안전 관리" 중 "현장 사진 아카이브" 불가.

**구현 방향**:
- 사진 촬영/선택 모달 컴포넌트 생성
- 카메라 API 또는 파일 선택으로 사진 첨부
- 사진 메타데이터(시간, 위치, 설명) 기록
- 퀘스트 완료 조건 연동 (3장 이상)

**관련 파일**:
- `src/data/questsData.js` — daily_photo_1 정의 (존재)
- `src/api/` — 사진 업로드 API (미존재)
- `src/components/` — 사진 업로드 UI (미존재)

### 4. 전직 전용 퀘스트 — 우선순위 ★★

**기획서 약속**:
> "전직 시 전용 퀘스트 해금"
> "유도원: 중장비 유도 체크리스트, 신호 시스템 퀘스트"
> "밀폐담당자: 밀폐공간 허가 관리, 산소 측정 체크리스트"

**현재 상태**: 전직 시스템은 작동하나, 전용 퀘스트 미정의

**상세 분석**:
- `specializationManager.js`에서 전직(클래스 체인지) 로직은 정상 작동
- `specializationData.js`에 전직 조건, 교육 요구 등 정의됨
- **`questsData.js`에 전직 전용 퀘스트가 하나도 없음**
- 퀘스트 필터링 `getQuestsByTypeAndRole()`이 역할(role)만 구분하고 전직(specialization)은 구분하지 않음

**영향도**: 전직 후 달라지는 것이 포인트 배율뿐. 기획서의 "전직 시 혜택" 중 "전용 퀘스트"가 공허함.

**구현 방향**:
- `questsData.js`에 전직별 전용 퀘스트 추가 (유도원/신호수/밀폐담당자 각 2~3개)
- 퀘스트 필터링에 `specialization` 조건 추가
- 전직 후 대시보드에 전용 퀘스트 표시

**관련 파일**:
- `src/data/questsData.js` — 전용 퀘스트 추가 필요
- `src/data/specializationData.js` — 전직 정의 (존재)
- `src/utils/specializationManager.js` — 전직 로직 (존재)
- `src/utils/questManager.js` — 퀘스트 필터링 수정 필요

## ⚠️ 부분 구현 항목 (Important)

### 5. 빨리감기 차단 — 로컬 영상만 작동

**기획서 약속**:
> "5초 이상 앞으로 건너뛰기 시 자동 감지 → 원래 위치로 복귀"

**현재 상태**: 로컬 비디오에서만 작동, YouTube에서는 미작동

**상세 분석**:
- `EducationVideoPlayer.jsx`(L67-92): 로컬 플레이어에서 **3초 기준** 탐지 구현 (기획서는 5초)
- 탐지 시 `maxWatchedTime`으로 복귀 + 경고 오버레이(L198-208) 표시
- `YouTubeEducationPlayer.jsx`: 누적 시청 시간만 추적(L125-150), **빨리감기 차단 없음**
- YouTube 임베드 API 특성상 seek 이벤트 차단에 한계

**구현 방향**:
- YouTube 플레이어에서도 `onStateChange` 이벤트로 seek 감지 시도
- 완전 차단이 어려우면, seek 감지 시 시청 시간 초기화 등 패널티 적용

**관련 파일**:
- `src/components/EducationVideoPlayer.jsx` — 로컬 플레이어 (구현됨, L67-92)
- `src/components/YouTubeEducationPlayer.jsx` — YouTube 플레이어 (미구현)

## 요약

기획서의 **가장 핵심적인 주장 3가지**와 실제 구현의 갭:

| 기획서 핵심 주장 | 근거 기능 | 구현 상태 |
|----------------|----------|:---------:|
| "안전교육 이수율 **100%**" | 교육 게이팅 | ❌ 미구현 |
| "매일 **체크리스트·사진·위험찾기** 수행" | 체크리스트 UI, 사진 업로드 | ❌ 미구현 |
| "**발견→검토→해결** 안전관리 사이클" | 역할별 워크플로우 | ⚠️ 부분 |

**Phase 1의 3개 항목(게이팅, 체크리스트, 사진)을 구현하면 기획서 약속의 핵심이 충족됩니다.**
