## 1. 프로젝트 개요

### 1.1 프로젝트 목적

**안전의 길(Safety Quest)**은 산업 현장의 안전교육, 안전점검, 위험요인 개선, 보상, 기록 관리를 하나의 참여형 안전관리 경험으로 묶는 게이미피케이션 플랫폼입니다. 기존의 일회성 집합교육과 서류 중심 점검을 매일 실행 가능한 마이크로 안전활동으로 바꾸고, AI 분석과 이력 추적을 통해 현장 안전행동의 실천율과 증빙력을 높이는 것을 목표로 합니다.

### 1.2 핵심 가치 제안

- **안전활동의 일상화**: 일간/주간/월간 퀘스트, 출석, 교육, 보상 루프를 통해 반복 참여 유도
- **법정 안전교육/점검의 디지털 기록화**: 교육 시청, 퀴즈, 체크리스트, 사진, 개선조치 이력 저장
- **위험요인 개선 사이클 관리**: 위험 발견, 완료 사진 업로드, 확인, PDF/Excel 증빙까지 연결
- **AI 기반 안전 분석**: Gemini 연동을 통한 위험 분석, 문서 보강, 사진 분석 기반 위험도 판단
- **현장 참여 보상 구조**: 포인트, 골드, 상점, 인벤토리, 보상센터, 랭킹으로 행동 동기 강화
- **작업중지권 보호 플로우**: 위험 신고, 처리 상태 관리, 불이익 신고와 보호 이력 관리

### 1.3 주요 사용자 페르소나

| 페르소나 | 역할 | 핵심 문제 | 서비스 가치 |
|---|---|---|---|
| 작업자 | 현장 근로자 | 안전교육과 점검이 부담스럽고 참여 동기가 낮음 | 짧은 퀘스트/교육, 즉시 보상, 작업중지 신고 |
| 안전 실무자 | 안전관리 담당 | 사진, 점검표, 교육 이수, 조치 내역이 흩어짐 | 기록 통합, 우선순위 정리, 보고자료 생성 |
| 관리감독자 | 현장 관리자 | 위험요인 처리 여부와 책임 이력 확인이 어려움 | 개선 사이클 추적, 승인/반려, 증빙 관리 |
| 운영 관리자 | 본사/관리자 | 참여율, 이수율, 조치율을 한눈에 보기 어려움 | 랭킹, 보상 승인, 안전점수, 컴플라이언스 리포트 |

## 6. 기술적 하이라이트

### 6.1 안전행동 게이미피케이션

프로젝트는 단순 안전관리 CRUD가 아니라, 안전행동을 반복하게 만드는 참여 구조를 갖추고 있습니다.

- 퀘스트, 출석, 스트릭, 포인트, 골드, 아이템, 업적, 랭킹, 전직센터를 연결
- 현장 안전활동을 사용자 성장과 보상으로 즉시 환류
- 개인 참여와 팀/부서 경쟁을 동시에 지원

### 6.2 법정 교육 데이터의 신뢰성 강화

교육 도메인은 영상 시청 체크포인트, 퀴즈 제출, 최종 이수 기록을 분리하여 저장합니다. `HashChainService`가 포함되어 있어 교육 기록의 사후 위변조 탐지와 감사 가능성을 높이는 방향으로 설계되어 있습니다.

향후 운영 검증에서는 다음 항목을 명확히 입증해야 합니다.

- 서버 시간 기준 이수 판정
- append-only 기록 정책
- 관리자 정정 이력과 감사 로그
- record hash / previous hash 검증 결과

### 6.3 위험요인 개선 사이클

`hazardcycle` 도메인은 위험 발견에서 완료, 확인, 공유, 증빙 생성까지 연결합니다.

- 위험 신고 및 사진 업로드
- 완료 사진 제출
- 확인/ack 기록
- 위험성 평가표 PDF 생성
- 월간 위험요인 개선대장 Excel 생성
- 인증번호 기반 검증 API

### 6.4 AI 기반 안전 분석

AI 도메인은 두 가지 방향으로 사용됩니다.

- **문서/텍스트 분석**: 위험분석, 문서 보강, 사업계획/안전문서 생성 보조
- **사진 분석**: 현장 사진 업로드 기반 위험도 분석

Spring AI와 Gemini 직접 호출 구조가 함께 존재하며, API 실패 시 기본 응답을 제공하는 Fallback 구조가 포함되어 있습니다.

### 6.5 PWA와 현장 사용성

현장 네트워크 품질이 낮을 수 있다는 점을 고려해 PWA와 오프라인 기반을 도입했습니다.

- Service Worker 기반 캐시
- IndexedDB 저장
- 오프라인 배너/상태 표시
- 백그라운드 동기화 준비

## 7. 주요 성과

### 7.1 MVP를 넘어선 서비스 구조 확보

초기 MVP의 체크리스트/위험성 평가/AI 분석에서 출발해, 현재는 교육, 보상, 랭킹, 작업중지, 위험개선 증빙까지 포함한 통합 안전관리 서비스 구조로 확장되었습니다.

### 7.2 공적 문제 해결 관점 강화

프로젝트의 중심은 단순 SaaS 판매가 아니라 산업안전의 참여율, 실천율, 기록 신뢰성을 높이는 데 있습니다. 특히 교육 시간을 짧은 마이크로 활동으로 나누고, 절감된 시간과 비용을 보상으로 환류하는 지속가능성 모델이 명확해졌습니다.

### 7.3 프론트엔드 시연 완성도 향상

사용자 흐름 기준으로 가입, 역할 선택, 대시보드, 퀘스트, 교육, 보상, 위험분석, 작업중지까지 이어지는 데모 시나리오가 구성 가능합니다.

### 7.4 백엔드 도메인 확장

백엔드는 20개 도메인으로 확장되어 단순 API 서버를 넘어 실제 운영 데이터 모델에 가까운 구조를 갖췄습니다. 특히 교육 무결성, 작업중지권, 위험개선 증빙, 보상 승인 같은 운영 기능이 추가된 점이 중요합니다.

### 7.5 제출/공모/시연 자료 기반 확보

`Docs`와 `docs`에 기획서, 구현 보고서, 백엔드 연동 가이드, API 명세, 교육/보상/작업중지 관련 문서가 축적되어 있어 발표, 공모전, 강사 피드백, 개발 인수인계에 활용할 수 있습니다.

## 10. 결론

### 10.1 현재 상태

2026-04-27 기준 **안전의 길(Safety Quest)**은 단순 MVP를 넘어, 실제 현장 안전활동의 반복 참여와 증빙 관리를 시연할 수 있는 **MVP+ 단계**에 도달했습니다. 프론트엔드는 36개 페이지와 80개 컴포넌트로 사용자 경험을 폭넓게 구현했고, 백엔드는 20개 도메인으로 인증, 교육, 보상, 위험개선, 작업중지권, AI 분석, 컴플라이언스 리포트까지 포괄합니다.

### 10.2 강점

- 안전교육, 점검, 위험개선, 보상을 하나로 묶은 통합 경험
- 공적 문제 해결 관점이 분명한 마이크로 안전활동 모델
- 게임화 시스템을 통한 반복 참여 동기
- AI 분석과 증빙 문서 생성 기반
- 작업중지권과 교육 무결성처럼 실무성이 높은 기능 포함
- 프론트/백엔드 모두 시연 가능한 수준의 넓은 기능 범위

### 10.3 보완 필요 영역

- 일부 프론트 API와 백엔드 엔드포인트 간 불일치 정리
- 로컬 상태와 서버 상태의 책임 분리
- 프론트 자동 테스트 및 핵심 회귀 테스트 추가
